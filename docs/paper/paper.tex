\begin{abstract}
Signed receipts for agent actions already exist; they attest who signed which
outcome. We study a complementary property: a third party can recompute the
decision from the record. A decision record keeps the inputs and frozen rules
of one go/no-go decision (a typed model answer, a policy-gated agent action
with human approval, an experiment promotion), and its verifier re-derives
the verdict without running a model. On 185 conformance vectors, a hash and JSON Schema check
accepts 36 of 64 tampered records that the verifiers reject. Of 4,214
single-leaf edits to valid records, the verifiers still reject 82.2\% after
the editor re-hashes (99.3\% while digests are stale). What passes is free text, caller-supplied labels such as the model
named in a proposed action, and edits that leave another consistent record.
All fixtures are synthetic; no agent or model is run.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Model output is not authority. Take the exported record of an agent action
that waits for human approval: proposal, frozen policy,
verdict and event history under a SHA-256 digest. Append an \code{EXECUTED}
event and a result, and recompute the digest. The file still validates
against its JSON Schema and its digest matches, so a check built from those
two tests accepts a record of an action that ran without approval. A
signature would stop this edit by anyone without the key. A verifier that
recomputes the verdict and walks the lifecycle stops it with no key at all.

Signed records are not the gap. More than ten 2026 Internet-Drafts and several
preprints define signed, offline-verifiable receipts for agent actions and
decisions
\citep[e.g.,][]{farley2026acta,schrock2026authorization,sharif2026aat,ardebili2026novafabric},
and one draft states that none of hash-chaining, signing or offline
verification is new to it \citep{sahu2026receipts}. A receipt attests who
signed which outcome. Most do not let a third party check that the outcome
follows from the inputs: the closest format excludes request content by rule
\citep{farley2026acta}, and the verification steps we read end at signatures,
digests or chain links. We study that complementary property. A
hash and JSON Schema check accepts 36 of 64 tampered records that
recomputation rejects; after re-hashing, the verifiers still reject 82.2\%
of single-leaf edits.

A \emph{record} keeps the inputs and the frozen rules of one go/no-go
decision. \emph{Replay} is recomputing the
deterministic part of that decision from inputs frozen in the record; a
\emph{verifier} replays a record and compares the result with what it states.
No verifier runs a model: the answer record stores the provider response,
which its verifier re-parses, and the action record stores only a model name
and a probability that the caller supplies. One draft \citep{sharif2026aat}
would call such a decision reconstructable, not reproducible, and replaying a whole agent run
\citep{ardebili2026novafabric} is a different operation. A \emph{label} is a
caller-written value that no verifier can re-derive.

We contribute (1) records and standard-library verifiers that recompute the
verdict at three decision points (Table~\ref{tab:points}); (2) a hash and
JSON Schema baseline and a single-leaf mutation sweep that measure what
recomputation adds, with every undetected field published; (3) lessons for
builders of such records; and (4) a stated boundary: what the records do not
bind for an LLM agent, and where receipts are ahead.

We concede four things. The envelope, canonical JSON, signing and offline
verification are reused, and the format is one more in a field with more than
ten. Proposer and reviewer are labels, so approval binding is weaker than
with approver-held keys \citep{schrock2026authorization}. A stand-alone record
has no chain and no trusted time, and it exposes its embedded inputs to its
holder. Every model answer, probability and proposal here is a synthetic
fixture: no model or agent is called, and the software has one author and no
outside user. Only version 0.1.0 of the packages is
published; what we evaluate beyond it is unreleased. Code, vectors and results: \repourl.

\section{Decision Records and Replay}
\label{sec:records}

Three independent Python packages write and verify these records
(Table~\ref{tab:points}). They use only the standard library and are not one integrated runtime. Each ships JSON Schemas
\citep{wright2022jsonschema} and valid, tampered and invalid vectors with
expected exit codes. A Node checker by the same author, sharing no code with
them, re-checks schemas and digests only. A fourth, unreleased benchmark is not evaluated.

The records follow five rules. (1) A record embeds the inputs of its decision
and the rules as data, such as thresholds and allowlists; the logic that
applies them is verifier code. (2) A schema version selects
exactly one canonical form, RFC 8785 \citep{rundgren2020jcs} in current
versions, and one set of replay rules. (3) To verify is to recompute, not to
compare hashes. (4) Exit code \code{1} means that the evidence disagrees,
\code{2} that the input is invalid or the check could not be made. (5) Limits
appear in the output: \code{digest-only} when a frozen external policy was
not re-evaluated, and \code{UNGATED}, never \code{PASS}, when an evaluation
of labeled cases ran without requirements.

The first package records answers of decision models such as Jev, a ``System
One'' API announced in September 2026 \citep{almeida2026jev} that answers
bounded questions with typed answers and reported probabilities. Preprints gate on such probabilities at set thresholds \citep{li2026jevjudge,shoham2026jevact};
whether they are calibrated is a question for such studies
\citep{deusser2026jev}, not for our fixtures.

The promotion package applies ordered rules to exported A/B aggregates
\citep{kohavi2020trustworthy}: a sample-ratio check first, then the primary
metric and its guardrails.

Signing is optional and reused: an in-toto Statement
\citep{torresarias2019intoto} in a DSSE envelope \citep{dsse2024spec} over the
SHA-256 of the record file's exact bytes, with an HMAC or Sigstore
\citep{newman2022sigstore}. Verifiers ignore signatures unless
\code{--require-signature} is given. A signature shows that a key holder
vouched for those bytes, not that the inputs are true, who the holder is (an
HMAC key is a shared secret), or when the record was made.

\section{The Approval Boundary of an Agent}
\label{sec:boundary}

The agent-facing package, decision-control, evaluates a proposal that a host
supplies. It calls no model and authenticates no one, and its two registered
actions only update a local SQLite ticket table.

\emph{Verdict order and stale state.} A frozen policy routes a proposal through eight checks
in a fixed order. Four hard constraints (wrong ticket, unregistered action, a
value off the allowlist, no change) give \code{DENY} before the probability
or the refusal is read. A refusal, or a probability that is missing or below
the policy minimum, gives \code{ABSTAIN}; a value on the review list gives
\code{REVIEW}, however high the probability; otherwise \code{ALLOW}. At execution,
a ticket that has moved from the frozen snapshot gives \code{STALE} instead
of an action: an approval covers a snapshot, not a standing permission.

\emph{Approval and separation of duties.} A \code{REVIEW} decision needs a
reviewer from the frozen list who is not the proposer. Replay applies the
rule to the exported file: a record edited to name the proposer as reviewer
fails with exit \code{1} even when re-hashed (three tampered vectors, and
one for a cancellation). The rule
compares labels and has two bypasses. An editor who also renames the proposer
and re-hashes passes. And replay applies the rules of the schema version a
record claims: the rule exists from schema 3, so a record rewritten as schema
2, which has no proposer field, passes with the same reviewer. A consumer has
to require a minimum schema version or a signature, and a signature still
does not show that two people were involved: a host has to add an identity
layer \citep{south2025delegation,kasselman2026aims}.

\emph{An external decision, bound to the whole proposal.} An OPA decision-log
entry \citep{opa2026decisionlogs} with its Rego modules, or a Cedar authorization \citep{cutler2024cedar} with
its policies and entities, can be frozen in the record. The frozen input must
equal the one derived from the record's complete proposal, ticket snapshot
and proposer: an early Cedar request omitted the model,
question version, probability and ticket revision, so one authorization was
accepted for different proposals. Replay re-evaluates the frozen policy when its engine is on
the PATH; otherwise it reports \code{digest-only} and exits \code{0}, or
\code{2} under \code{--require-reevaluation}.

\emph{A framework's approval interrupt.} The Model Context Protocol says
there ``SHOULD always be a human in the loop with the ability to deny tool
invocations'' and defines no record of the approval \citep{mcp2026spec}; a
framework's approval interrupt saves the run state and resumes when a person
answers \citep{langchain2026interrupts,openai2026agentshitl}. That says a
human resumed the run, not who, under which frozen rules, or what was
decided. Our example maps a LangGraph interrupt onto submit and approve or
reject, and leaves a record that replays (Appendix~\ref{app:langgraph}).

\section{Evaluation}
\label{sec:evaluation}

\emph{Corpus and threat model.} The corpus is the three packages' conformance
vectors: 185 vectors (56 valid, 64 tampered, 65 invalid); the valid ones span
eleven record types and schema versions. A tampered vector must make
its verifier exit \code{1}, an invalid one exit \code{2}. Verifiers run as
black-box subprocesses on a PATH without OPA, Cedar or \code{cosign}, and
return the manifest's exit code on 185 of 185. Our editor holds an exported,
unsigned record and no signing key, and can change any field, recompute every
digest and choose the schema version, which nothing outside the file pins. Out of scope: a fabricating producer, a key holder, a modified verifier.

\emph{Baseline.} The baseline does what a consumer without a replaying
verifier can do: every declared document validates against its JSON Schema,
and every digest that can be recomputed from the vector matches. It accepts 36
of the 64 tampered vectors (Table~\ref{tab:baseline}); the 28 it
rejects all fail a digest check, none a schema. The verifiers' 64 of 64 is by
construction, since a tampered vector is by definition one its verifier
rejects; the informative number is the 36. These are edits whose digests are
consistent: a disposition changed from \code{FAIL} to \code{PASS}, an
\code{EXECUTED} event appended to a pending \code{REVIEW} decision, an answer
probability changed to 0.99, each re-hashed. Four of the six experiment-gate
cases need no re-hash: that record's digest covers only the input, so only
replay ties the output to the input.

\emph{Mutation sweep.} The tampered vectors are hand-picked, so we also edit
every JSON leaf of every valid vector once, as in mutation testing
\citep{jia2011mutation}: a number is changed, a string gets a character
appended, a boolean is flipped, a null is replaced
(operators and the few files left alone: Appendix~\ref{app:types}). Each of the 4,214 edits runs twice. \emph{Stale} leaves every digest as it was,
as an accidental change would. \emph{Resealed} recomputes every digest the
verifier checks, in the canonical form the edited schema version requires, as
our editor would. An edit counts as detected on a non-zero exit.

Stale, 4,184 of 4,214 edits are detected (99.3\%); that rate is a property of
the digests, and the 30 misses are two version labels that the
experiment-gate digest does not cover. Resealed, 3,466 are detected (82.2\%)
and 748 pass (Table~\ref{tab:sweep}). By record type the rate runs from
68.4\% for the agent-facing record, decision-control record v5 (527 of 770),
to 96.8\% (Appendix~\ref{app:types}). We
did not run the baseline on the edited records, so the sweep measures the
verifiers: what recomputation adds over hash and schema checks is measured on
the 64 tampered vectors only, and we cannot say how many of the 717
invalid-input rejections a schema alone would give. As a control, all 56 valid vectors verify when rewritten unmutated.

\emph{What binds an edit.} Binding by recomputation is a property of an edit,
not of a field. A resealed edit is rejected when it changes a value that
replay recomputes or compares with a copy elsewhere in the record; otherwise
only a stale digest gives it away, and only a signature over the file would
bind it. The 748 that pass are listed by field in Appendix~\ref{app:fields};
the results give no count per kind. They are free text; labels such as a recommendation's model name or the
proposer; inputs whose new value yields the same verdict, such as a minimum
probability; content of a frozen external policy that was not re-evaluated;
and a schema version whose successor reads the same record. The third kind is an equivalent mutant
\citep{jia2011mutation}: the edit leaves another consistent record, which a
recomputing verifier is right to accept. Replay establishes that the verdict
follows from the recorded inputs, not that those inputs are the original
ones.

\emph{One edit, two records.} Append a character to a model name and reseal.
In the Jev answer record the edit is rejected, because the verifier
re-derives the model from the stored response. In the decision-control record
it passes in every record version: that record stores a label in place of the output
behind it, and for an agent this is the label that matters most. The answer
record's protection is itself single-leaf: change the name in both places of
the file, re-hash, and it passes. Replay shows that label and stored response
agree, not that a provider sent either.

\emph{Re-evaluating a frozen policy.} With OPA 1.21.2 on the verifier's PATH,
8 more resealed edits are detected (3,474 of 4,214, 82.4\%): edits to the
frozen Rego module and query path in record v5, which digest-only replay
cannot see. This is why \code{digest-only} has to be a visible outcome. Re-evaluation catches an
edited policy only when the evaluated outcome changes, and Cedar, on neither
PATH, was replayed digest-only throughout.

\emph{What the rates do not show.} One edit per value type, one leaf at a
time, on vectors written by the author of the verifiers: the rates describe
this corpus and operator, not records in general, and not an editor who
changes several fields together or lowers a schema version, which the sweep
never does. The baseline is our own construction and models no receipt format; no
receipt implementation was run. Signatures are not exercised, and we
report no latency. An earlier version of the sweep
resealed only the digests the manifests declare, and 34
edits counted as detected only because a digest stayed stale or was sealed in
the wrong form.

\section{Lessons}
\label{sec:lessons}

\emph{One file, two decisions.} One invalid vector has a
first \code{"decision": "HOLD"} member before the real one: a last-wins
parser reads a record that would otherwise verify as \code{SHIP}, a
first-wins parser reads \code{HOLD}. Parsers disagree on such input
\citep{seriot2016json,miller2021json} and JSON Schema validators do not see
duplicate keys: read as \code{JSON.parse} does, the baseline accepts 12 of
the 65 invalid vectors instead of 6, all six extra being duplicate-key
vectors. So current schema versions reject duplicate keys, NaN, Infinity and
integers beyond $2^{53}-1$ when parsing. Older versions keep their
readers: the rule holds per schema version, not per verifier.

\emph{Fail closed; exit codes are verdicts.} A recurring defect was a check
that passed when its input was missing: a missing probability that became
1.0, a JSON \code{null} read as an option not given, a NaN threshold that
compared false with everything. Exit codes had the same flaw: where \code{1}
means that the evidence is wrong, an uncaught exception, on which Python
exits \code{1}, is a false verdict; all three verifiers needed that fix. An
ungated evaluation still exits \code{3} in jev-decision and \code{0} in
decision-control.

\emph{Make digests and floats recomputable elsewhere.} A digest over Python's
\code{json.dumps} cannot be recomputed in another language: one \code{2.0} in
an example input gives a SHA-256 starting \code{c0b34a77} in Python and
\code{c1ff2af0} under RFC 8785 or in Node, so new schema versions use RFC
8785. By the repository's account, five of
seven bundled experiment-gate 0.1.0 records made on macOS failed exact replay
on Linux, where the math library differs in the last digit. Derived floats
are now compared at relative $10^{-9}$, so a smaller edit to a derived
statistic goes undetected; everything else stays exact.
Once records replay, a numerical fix needs a new schema version.

\section{Related Work}
\label{sec:related}

The draft of \citet{farley2026acta} defines a signed receipt per
access-control decision; its receipts ``capture decision
metadata, NOT request content'', so a verifier learns that an issuer signed a
denial, not that the denial follows from policy and request. The draft of
\citet{msebenzi2026evidence} lets a third party ``recompute every verdict
from signed primitives''; as we read it, those verdicts (\code{VALID},
\code{INVALID}, \code{UNVERIFIABLE}) are the outcome of verifying a record,
not a system's allow or deny. The AgentBound preprint
\citep{kaul2026agentbound} is nearest to our gate as a design: actions are
permitted, reviewed or denied before execution, with co-signed receipts
``enabling independent replay verification''. We found no repository for it;
we add vectors and a measurement, and lack its delegation model. The NovaFabric preprint seals a whole agent run with a trusted timestamp and
a Merkle log, which we lack, and reports three tamper classes rejected and 140 single
mutations localized \citep{ardebili2026novafabric}. With one tampered vector \citep{msebenzi2026evidence}
and a test-vector section \citep{farley2026acta}, those are the nearest
measurements we found; we found no comparison of recomputation with digest and schema checks.

The in-toto Simple Verification Result ``does not include information for reproducing the
verification result'' \citep{hennen2026svr}. Our records keep that kind of
information for their own decisions, and could travel as the payload or
subject of an existing envelope, such as a signed statement in a transparency
service \citep{birkholz2026scitt}; we have not built that. An
attestation-aware promotion gate for LLM artifacts has been proposed
\citep{tan2026attesting}; we did not find a promotion decision over A/B
aggregates kept as a recomputable record. Decision provenance,
reviewability and agent visibility asked for such records earlier
\citep{singh2019decision,cobbe2021reviewable,chan2024visibility}, without a
format or verifier.

\section{Limits and Next Steps}
\label{sec:limitations}

For an LLM agent, seven things are not bound. (1) The raw model or tool-call
output behind a proposed action is not in the action record. A chained
example puts an answer record's digest into the model label and prints
``Only this recipe checks that link. No verifier does''; storing the output
and re-deriving the proposal is proposed, not built. (2) Proposer,
reviewer, producer and model identities are caller-asserted; no record
authenticates the provider. (3) Execution is local; nothing shows an effect
in an external system. (4) There is one record per decision: no trajectory or
multi-agent record, no hash chain across records, and nothing shows that
every decision produced a record. (5) Sampled actions (bandit or RL
policies) are not recorded. (6) There is no trusted time; only
decision-control records timestamps, from the local clock. (7) No agent or
model runs in any example, and we report nothing on an agent benchmark such
as AgentDojo \citep{debenedetti2024agentdojo}. On identity (approver-held
keys bound to one canonical action, \citealp{schrock2026authorization};
one-shot credentials for the exact bytes that will run,
\citealp{jing2026separation}), on chaining and completeness
\citep{sharif2026aat} and on trusted time \citep{ardebili2026novafabric},
existing work is ahead.

A producer who fabricates a self-consistent record passes replay: the party
that writes the record is the party being audited
\citep{figuera2026notarized}, and agents can tamper with their own traces
\citep{qin2026tamper}. A transparency service is the kind of remedy.
Embedding the inputs makes recomputation possible and exposes them to
whoever holds the record; receipts leave them out on purpose
\citep{farley2026acta}, and we offer no redaction. A human approval step
invites rubber-stamping: one vendor reports that users accept 93\% of its
coding agent's manual permission prompts \citep{hughes2026automode}. A record
shows that an approval was written down, not that the review was careful.
Planned and not yet started: an unaffiliated reproduction and a pilot under a
protocol frozen before any result.

\section{The LangGraph Mapping}
\label{app:langgraph}

The example is in \code{ai-workflows/decision-control/examples/langgraph/}
and is not part of the package, which never imports LangGraph. A
\code{propose} node submits the proposal, which freezes proposal, policy and
verdict. A \code{review} node calls \code{interrupt()} with the pending
decision as payload. \code{Command(resume=...)} carries the decision, the
reviewer and a note to approve or reject, after the store has checked the
frozen reviewer list and refused the proposer. The end of the review node
exports the record. Only a \code{REVIEW} verdict interrupts.

Two traps were met. A node re-runs from its first line on resume, so a node
that submitted and then interrupted would submit twice: submit and interrupt
are separate nodes. And LangGraph keeps the resume value of a node that
raised and gives it to the next attempt (observed with langgraph 1.2.16), so
a refusal is returned as state, not raised. The example has no model call:
its proposal is a hand-written literal. Thread and checkpoint identifiers go
into the review note, which replay treats as free text.

Three details of the package that Section~\ref{sec:boundary} leaves out. The
registered actions are \code{reassign_ticket} and \code{set_ticket_priority}.
A built-in verdict and a frozen external verdict combine by taking the more
restrictive one, in the order \code{DENY}, \code{ABSTAIN}, \code{REVIEW},
\code{ALLOW}. And the corpus holds three tampered vectors in which the
reviewer is set to the proposer (record v3, v4 and v5) and a fourth in which
the cancelling reviewer is; replay rejects all four with exit \code{1}.

\section{Reproduction}
\label{app:repro}

The cross-language check and the evaluation run from a checkout of the

V=/tmp/ads-venv; W=../../ai-workflows

  DEMO_OUT=/abs/new/dir
\end{verbatim}

\code{RESULTS.md}; with latency measurement off, as here, its output is
