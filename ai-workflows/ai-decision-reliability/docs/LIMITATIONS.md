# Limitations

1. All results are on synthetic data. They do not establish real-world commercial performance, legal compliance, fairness across real populations, consumer benefit, or transferability to any particular organization.
2. The performance thresholds are proposed engineering values chosen before the 0.1.0 results were produced. They are not government or industry standards and have not yet been reviewed by an unaffiliated party. The minimum 12-case review-fixture denominator was added in 0.1.1 after review exposed that 0.1.0 could pass that gate with no observed critical cases. Candidate 0.1.2 separated expected fixture labels from the router and added a zero-misroute condition. Specification candidate 0.1.3 connected that tested router to the live decision path, blocked worst-slice evaluation when zero slices meet the minimum size, and changed the input guard from a three-field denylist to an authorized-feature allowlist. Package candidate 0.1.4 adds release-control corrections: a primary BLOCK now returns a failing process status, and a nonempty output location is refused. These are correctness and control repairs made after results were viewed.
3. The first development run was blocked by the gates (small held-out partitions and a nearly linear ground truth under which the baseline won). The generator was then enlarged and given non-linear structure before the 0.1.0 candidate values were recorded. Later review produced the 0.1.1, 0.1.2, and 0.1.3 specification corrections and the 0.1.4 package-control repair described in the development log. A benchmark adjusted during development is weaker evidence than one fixed in advance. The five seeds vary model training rather than the underlying dataset, and the comparative gates are point estimates, not tests of statistical superiority. Any semantic change to metrics, gates, or protocol—or any change after maintainer acceptance and freeze—requires a new candidate version and regenerated results. Before that freeze, metadata or corrective text repairs must be logged and generated artifacts regenerated when their content changes. Maintainer review and a public freeze remain pending.
4. Isotonic calibration and the stability check are evaluated in-process. Package candidate 0.1.5 has no deployed service, so availability, error rate, and service-level latency are not measured; `runtime.json` is in-process timing on one machine.
5. Human review is represented by a deterministic router tested against independent expected labels on a fixed fixture. It proves only that the reference routing rule selects the 12 specified required cases and rejects four specified controls; no person reviewed a case and no queue delivery, reviewer response, override quality, workload, or human-factors outcome was evaluated.
6. The ranking module evaluates ordering quality on a synthetic candidate set only. It does not cover corpus retrieval recall, marketplace supply response, or real customer behavior.
7. The guarded-update result in package candidate 0.1.5, under specification 0.1.3, is evaluated on all five seeds and rejected because the per-gate worst values fail log-loss delta and worst-slice ECE on different seeds. Local validation retained the adverse decision from 0.1.4. Ranking remains the sole excluded update gate. `current_reference` is a simulation label; no service is deployed or in production.
8. For two fresh runs in one executing environment, only `results.json` and `MANIFEST.json`—and the SHA-256 of each file—are expected to be byte-identical. Machine-dependent `runtime.json` is excluded. Equality with the stored result hash is limited to the attested producing environment with the same dependency artifacts and execution settings. Any other run requires tolerances for every compared numerical field fixed before execution, including per-seed metrics, plus unchanged exact invariants: decisions, gate dispositions, counts, versions, seeds, exclusions, and dataset identity. A comparison helper does not supply an engineering rationale for the selected tolerances. See [`REPRODUCE.md`](REPRODUCE.md).
9. This is an unreleased candidate. Actor-level attribution and version-by-version provenance remain incomplete. The destination monorepo already exists, but no accepted standalone project release commit, cleared project license, annotated release tag, third-party reproduction, adoption, or operational use is claimed. Integration does not date this project's development to the monorepo's earlier history. A project-tree/export-tree match proves content identity only.
10. Candidate 0.1.5 adds monorepo integration, comparison tooling, and publication records without changing specification 0.1.3's generator, metrics, or gates. A local integration test or fresh local clone is development validation; it does not meet the clean-machine/account and unaffiliated-reviewer conditions by itself. Rights review, maintainer acceptance, independent reproduction, and publication have separate records.
